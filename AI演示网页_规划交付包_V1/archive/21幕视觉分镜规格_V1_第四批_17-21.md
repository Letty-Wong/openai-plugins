## 1. 本批任务

第 17—21 幕承担整套演示的最后五个任务：

1. 把 Scene 16 已经形成的安全边界落实为可理解、可执行的四条红线，而不是一页抽象合规口号。
2. 说明安全边界的目的不是阻止使用，而是让产品资料、业务输出和执行动作进入可控流程。
3. 把四条安全边界自然转化为四个场景诊断方向，回答“企业第一个 AI 场景从哪里开始”。
4. 把诊断结果展开为 `今天 → 30 分钟 → 3 天 → 3 个月` 的清晰行动路线，并明确各阶段的成果与边界。
5. 让前面持续存在的接入环、真实产品、资料包、审核节点和第一个场景在结尾闭合成企业能力回路，同时完成 CTA 与 Q&A 交接。

本批不是五张结尾页，而是一条持续变形的路径：

```text
Scene 16 的 SafetyBoundary 与四个入口
→ Scene 17 资料入口展开为三级资料门
→ 工具入口展开为白名单准入门
→ Scene 18 内容进入人工审核
→ 高风险执行进入权限确认
→ 四条边界全部完成
→ SafetyBoundary 转为 ScenarioRadar
→ Scene 19 扫描四个业务条件与多个候选场景
→ 锁定一个第一个场景
→ 扫描环从缺口处展开成 ActionPath
→ Scene 20 依次经过今天、30 分钟、3 天、3 个月
→ 第一个样板进入持续能力循环
→ Scene 21 路线重新闭合为完整接入环
→ 真实场景填补最初的缺口
→ 最终 CTA 与 Q&A 入口出现
```

本批的核心判断：

> 结尾不能只是“扫码报名”。观众必须看见：边界如何保护使用，诊断如何选择场景，场景如何跑成样板，样板如何沉淀为能力。

## 2. 本批内容判断与边界

### 2.1 四条红线不是四个禁止图标

四条红线分别解决四种不同问题：

```text
资料红线：什么可以进入
工具红线：资料进入哪里
内容红线：什么可以对外发布
权限红线：AI 可以做到哪一步
```

对应的视觉动作必须不同：

```text
资料：分级 / 遮罩 / 阻断
工具：准入 / 来源核验 / 白名单
内容：核对 / 修订 / 批准
权限：确认 / 授权 / 执行
```

禁止把四条红线都做成相同的锁图标、盾牌卡片或红色警告框。

### 2.2 安全章节不是完整合规课程

主演示只讲老板必须理解的操作边界，不展开：

- 法律条文细节。
- 具体厂商的数据处理协议比较。
- 地域存储与合规认证清单。
- 网络安全架构。
- 自动化系统权限模型的技术实现。

所有具体企业制度、法律判断和工具准入规则，都应在后续诊断或陪跑中根据真实企业情况确认。

### 2.3 场景诊断不是自动评分器

Scene 19 的扫描器负责帮助观众理解判断方法，不输出伪精确分数，也不声称页面自动判断企业成熟度。

允许：

```text
四个判断方向
候选场景的相对匹配状态
一个示例场景被锁定
现场自测二维码
```

禁止：

```text
83 分 AI 成熟度
预计提升 47%
自动推荐“最佳场景”
没有真实数据支撑的 ROI
```

### 2.4 行动路线是成果路径，不是服务承诺堆叠

每个阶段只回答两个问题：

```text
这一阶段要判断或完成什么？
这一阶段不承诺什么？
```

尤其必须明确：

- 3 天不承诺完成全公司 AI 改造。
- 3 天不是无限代做图片、视频和文案。
- 3 个月不是纯上课，而是资料、人员、流程、安全和复盘的持续固化。
- 是否进入体验课或陪跑，应由诊断、资料条件与负责人参与度决定。

### 2.5 CTA 的信息层级

最终页默认只显示一个主二维码，建议对应一张统一表单：

```text
填写企业自测
申请 30 分钟诊断
勾选是否愿意进入 3 天体验课
```

如果实际业务必须使用多个链接：

- 默认只显示主入口。
- 讲师通过控制键切换二维码。
- 不在同一屏同时摆放三个大二维码。
- 所有二维码旁必须有文字短链或编号作为降级。

### 2.6 本批绝不展示

- 真实客户名单、报价单、合同和财务文件。
- 未经脱敏的邮件、聊天记录或员工信息。
- 未确认的工具安全结论。
- 虚构的企业诊断结果。
- 虚构名额、截止日期或稀缺性文案。
- “一键完成企业改造”等过度承诺。
- 复杂的法律警示长文。
- 三个以上同时争夺注意力的 CTA。

## 3. 最后一章全局视觉规格

### 3.1 空间迁移

第 17—21 幕的空间连续关系：

```text
17—18：安全空间
近黑背景 / 透明结构门 / 暗色红光产品 / 冻结业务卡

19：诊断空间
近黑逐渐变为深灰 / SafetyBoundary 旋转展开为扫描雷达

20：行动空间
扫描环从缺口展开为前进路线 / 背景逐步恢复暖白与清晰结构

21：能力空间
路线重新闭合 / 暖白与近黑形成高对比终幕 / 产品、文字与完整接入环同台
```

背景不应逐幕整屏切换。由同一个 `BackgroundSystem` 通过遮罩、亮度和结构线连续变化。

### 3.2 持续对象

#### A. `SafetyBoundary`

Scene 16—18 的核心容器。

```text
Scene 16：包围产品、资料和输出的四入口防护结构
Scene 17：资料门与工具门依次展开
Scene 18：内容门与权限门依次展开
Scene 18 结束：四条边界形成完整操作回路
Scene 19：外层结构旋转、伸展为四个诊断方向
```

禁止 Scene 19 重新绘制一套完全不同的雷达。

#### B. `ProductStage`

Scene 17—21 仍然是同一个花洒对象。

```text
17—18：作为真实业务资产被保护和检查
19：缩为中心样板，成为候选场景的参照物
20：进入“第一个样板”节点
21：恢复主视觉比例，与最终巨型文字和完整接入环形成前后遮挡
```

#### C. `SourcePacket`

```text
17：接受资料分级与脱敏
18：为内容审核提供事实来源
19：作为“已有资料条件”的诊断证据
20：进入 Day 1 的资料与边界成果
21：成为完整能力回路中的资料节点
```

#### D. `OutputCards`

```text
17：作为可能包含敏感字段的检查样本
18：经过审核与权限确认
19：缩为候选场景的结果样板
20：进入 Day 2 的可见样板
21：作为业务复用节点回到闭环
```

#### E. `HumanReviewNode`

Scene 18 新增并持续到结尾。

```text
作用：区分 AI 起草与企业确认
视觉：一个具有明确入口、核对区域和批准出口的节点
禁止：使用卡通人物头像或“万能审批”图标
```

Scene 20 中转化为 Day 3 的审核规则，Scene 21 中成为能力回路的固定节点。

#### F. `ScenarioRadar`

由 `SafetyBoundary` 变形而来。

```text
四轴：重复最多 / 资料最散 / 最缺模板 / 30 天可验证
中心：企业现有资料与真实产品
候选：销售、内容、视频、外贸、客服、行政、安全规范等场景
```

#### G. `ActionPath`

由 `ScenarioRadar` 的分段环从缺口处展开。

```text
节点 1：今天
节点 2：30 分钟
节点 3：3 天
节点 4：3 个月
```

不是一条普通进度条，而是接入环被拉直后的同一个对象。

#### H. `CapabilityLoop`

Scene 21 的最终状态。

由 `ActionPath` 重新闭合，五个分段对应：

```text
判断
生成
边界
诊断
落地
```

中间保留资料、场景、AI 辅助、人工审核、业务输出与复用回流。

#### I. `QRDock`

Scene 19 可作为自测入口短暂出现，Scene 21 作为最终 CTA 完整出现。

```text
二维码
入口名称
短链 / 编号降级
网络状态提示
主办信息
```

二维码是 UI 组件，不嵌入背景图。

### 3.3 固定图层

建议：

```text
z 10  BackgroundSystem
z 20  环境结构线与低强度粒子
z 30  ActionPath / ScenarioRadar 后层
z 40  ProductStage 与 SourcePacket
z 50  SafetyBoundary / ReviewNode / MilestoneShell
z 60  OutputCards / CandidateTokens
z 70  后景巨型文字
z 80  产品或结构穿字层
z 90  前景文字切片与章编号
z 100 PresenterControls / QRDock / QAPanel
```

安全门、扫描轴与行动路线使用同一套 SVG 坐标系，避免跨 Scene 跳位。

### 3.4 色彩迁移

沿用前批颜色，并增加终幕亮色：

```css
--void: #08090B;
--void-raised: #111318;
--paper: #F1EEE6;
--paper-raised: #FBF8F2;
--ink: #111318;
--signal: #E63A2E;
--signal-hot: #FF584A;
--line-light: rgba(241, 238, 230, .20);
--line-dark: rgba(17, 19, 24, .18);
--glass: rgba(241, 238, 230, .08);
--muted: #777C83;
--blocked: #403F42;
```

规则：

- `可用 / 已审核 / 已确认` 不额外使用绿色；通过结构完整、实线和高对比表达。
- `待确认` 使用虚线、斜纹和信号红小标，不使用黄色警告色。
- `禁止进入` 使用失去连接、低对比和实体门阻断，不使用持续闪烁。
- Scene 20 开始逐步恢复暖白，表示从风险判断进入可执行路径。
- Scene 21 的信号红只用于闭合缺口、CTA 和关键结构，不铺满全屏。

### 3.5 四类动作语法

```text
资料：经过三层门，发生保留、遮罩或阻断
工具：通过准入门，显示来源路径是否可确认
内容：穿过审核节点，发生核对、修订与批准
权限：在执行前停靠，等待明确确认
```

诊断和行动的方向语法：

```text
诊断：向四周扫描，再向一个点收敛
行动：由环向前展开，再由线重新闭合
结尾：缺口被真实样板填入
```

### 3.6 信息诚信

安全示例只展示抽象、去敏或演示数据：

```text
公开产品手册
脱敏后的项目需求
遮罩后的联系人字段
待确认的 MOQ / 质保
未知来源工具
人工审核状态
```

禁止把演示中的假数据伪装成实际企业制度。

诊断结果必须标记为：

```text
示例判断
现场自测
需进一步诊断
```

行动路线中的成果使用“目标 / 交付物 / 判断结果”表述，不使用保证式结果。

### 3.7 动效节奏

本批情绪由“收紧”逐步过渡到“展开”：

```text
17：精确、克制、门式动作
18：停靠、审核、确认
19：缓慢扫描、快速锁定
20：稳定向前、节点展开
21：路线闭合、文字与产品完成最后一次大幅运动
```

参数建议：

```text
门开合：500—850ms
遮罩脱敏：350—550ms
审核通过：450—700ms
扫描一轮：1200—1800ms
候选锁定：500—800ms
路线展开：900—1400ms
终幕闭合：1100—1600ms
```

讲解状态中：

- 安全门不持续开关。
- 扫描雷达只保留非常缓慢的一圈结构光。
- 行动路线只保留 1—2px 的方向流动。
- 终幕接入环呼吸缩放不超过 0.8%。

### 3.8 投影、离线与二维码

- 1920 × 1080 为主设计画布。
- 1366 × 768 下标题与二维码不能被浏览器 UI 遮挡。
- 二维码显示面积建议不小于 220 × 220 CSS px。
- 主二维码必须离线加载，不依赖远程生成服务。
- 所有链接同时提供短链或报名编号。
- Scene 19 的自测计时器默认不自动开始，由讲师按键启动、暂停或重置。
- 没有最终链接时，二维码区域显示 `CTA_PLACEHOLDER`，不使用可误扫的随机码。

# Scene 17 — 资料与工具：先分级，再接入

## 1. 叙事目的

把 Scene 16 的前两个安全入口展开为具体可执行的判断：

```text
资料先分级
工具先准入
```

这幕要让观众理解：企业不是“所有资料都不能给 AI”，也不是“随便找一个好用工具就可以上传资料”。正确顺序是先判断资料等级，再判断工具是否在企业可确认的使用范围内。

本幕不要求观众记住复杂制度，只需要带走：

> 哪些资料可以用，哪些需要脱敏，哪些禁止进入；企业资料只进入可确认的工具。

## 2. 屏幕文案

章节标：

```text
01 / 04
资料红线
```

主标题第一阶段：

```text
哪些能用
哪些要脱敏
哪些不能进入
```

三级资料门：

```text
可用
脱敏
禁止上传
```

章节标第二阶段：

```text
02 / 04
工具红线
```

工具问题：

```text
数据去了哪里？
谁能看到？
是否会被保存？
```

最终停留句：

```text
先分级
再接入
```

辅助句：

```text
企业资料，只进入可确认的工具
```

## 3. 构图

起始构图继承 Scene 16：

```text
ProductStage：x 50 / y 52 / scale .64
SourcePacket：产品左下偏中
OutputCards：五部门位置，低对比冻结
SafetyBoundary：围绕全部业务对象
资料入口：前景激活
工具入口：次前景待机
内容 / 权限入口：后层待机
```

资料门展开后：

```text
左侧 42%：三级资料门
中部：待检查资料卡通过门
右侧 38%：产品和已被保护的业务对象
```

进入工具阶段后，三级资料门折叠到边界左侧成为已完成模块；工具入口从上方或右上展开为一个准入门，画面轴线从水平资料流转为略带纵深的接入路径。

## 4. 图层结构

```text
近黑背景
SafetyBoundary 后层
ProductStage / SourcePacket / OutputCards
资料样本卡
三级资料门
脱敏遮罩层
禁止进入实体门
工具准入门
工具来源路径线
主标题与章节标
边界状态汇总
```

资料卡必须保持真实文档感，但不仿制任何实际企业文件。

## 5. 起始帧

继承 Scene 16.6：

- `资料`入口向前半层。
- 其他三个入口后退。
- 产品、资料包和输出卡对比度约 55%。
- 左侧显示 `01 / 04 资料红线`。
- 全部 pointer parallax 关闭。

## 6. Beat 设计

### Beat 17.1 — 资料入口展开为三级门

讲师触发：“不是所有资料都能直接给 AI。”

运动：

```text
资料入口从 SafetyBoundary 边缘向左展开
一条连续通道分成三层：可用 / 脱敏 / 禁止上传
三层不是三张并排卡片，而是同一条路径上的三个判断结果
ProductStage 保持不动
```

视觉重点：

- `可用`门保持完整连接。
- `脱敏`门中间增加一层可移动遮罩。
- `禁止上传`门为实体终止面，路径在此不再继续。

### Beat 17.2 — 公开资料直接进入

讲师触发：公开产品资料、官网介绍、公开宣传册可以作为低风险起点。

示例卡：

```text
公开产品手册
产品图片
公开功能说明
官网介绍
```

运动：

```text
一张公开产品资料卡从左侧进入
经过“可用”门时结构线保持连续
卡片进入 SourcePacket 的公开资料层
SourcePacket 对应层亮起
```

不要使用绿色勾号。通过完整实线、正常对比度和无阻断表达通过状态。

### Beat 17.3 — 敏感字段先脱敏

讲师触发：有些资料可以使用，但必须先脱敏。

示例卡：

```text
项目需求摘要
联系人字段
客户公司信息
内部备注
```

运动：

```text
资料卡进入“脱敏”门
姓名、电话、邮箱、公司识别字段被矩形遮罩覆盖
保留与场景判断有关的需求描述
遮罩完成后，卡片才继续进入边界
```

遮罩应像信息层被真实覆盖，而不是整卡模糊。

卡片角落显示：

```text
已脱敏示例
```

### Beat 17.4 — 高敏资料被阻断

讲师触发：客户名单、合同、报价、财务、核心技术、员工隐私不能随便上传。

示例 token 从通道依次接近：

```text
客户名单
合同
报价
财务
核心技术
员工隐私
```

运动：

```text
这些 token 接近“禁止上传”门
门保持关闭
连接线在门前结束
对象不爆炸、不报警，只失去前进路径并退回边界外的受控存放区
```

屏幕短句：

```text
禁止进入 ≠ 删除资料
而是保持在受控范围
```

### Beat 17.5 — 资料边界形成

# Scene 18 — 内容与权限：生成可以快，发布和执行必须确认

## 1. 叙事目的

完成安全章节的后两条红线，并把 AI 的角色明确限定为：

```text
可以起草
可以整理
可以建议
不能替企业确认事实
不能在没有授权的情况下执行高风险动作
```

这幕要让观众看到两个不同风险层级：

1. 内容是否可以对外发布。
2. 系统动作是否可以真正执行。

内容审核与权限确认不能合并成同一个“人工按钮”。前者核对事实与表达，后者决定是否发生真实业务动作。

最终判断：

> AI 可以帮你快，但不能替你确认事实，也不能越过权限直接执行。

章节标第一阶段：

```text
03 / 04

```

内容路径：

```text

修订
批准
```

需核对字段：

```text

价格
质保
承诺
案例
```

章节标第二阶段：

```text
04 / 04
权限红线
```

权限判断：

```text
生成 ≠ 执行
```

动作层级：

```text
起草
发送
报价
操作
```

最终停留句：

```text
生成可以快
发布和执行必须确认
```

辅助句：

```text
边界不是为了少用，而是为了放心用
```

## 3. 构图

起始时：

```text

上方：工具准入模块
中部：ProductStage 与 SourcePacket
右侧或右下：内容入口激活
```


```text

```

画面要清楚表现：有内容批准，不代表自动获得执行权限。

- 产品和资料包保持可见。
- 左侧主标题仍为“先分级，再接入”，即将退为背景判断。

## 6. Beat 设计

### Beat 18.1 — 内容入口展开为审核路径

讲师触发：“AI 生成内容可以作为初稿，但对外发布前必须审核。”

运动：

```text

路径上依次出现：初稿 / 核对 / 修订 / 批准
```

主标题切换为：

```text
生成的是初稿
```

### Beat 18.2 — 需要核对的字段被看见

讲师触发：产品参数、价格、质保、承诺、法律财税、客户案例和竞品比较不能直接发布。

运动：

```text
OutputCard 内部不可信或待确认字段被逐项圈出
参数 / 价格 / 质保 / 承诺 / 案例五个字段标记浮到审核节点上方
每个字段连接回 SourcePacket 的对应来源或 PLACEHOLDER
```

没有来源的字段显示：

```text
待人工确认
```

禁止自动生成一个看似真实的替代值。

### Beat 18.3 — 错误承诺被阻止

讲师触发：AI 不能替企业确认事实。

使用一个明确标注为“演示错误”的示例：

```text
质保：5 年？
```

视觉处理：

```text
该字段以虚线和问号进入审核节点
SourcePacket 中没有对应已确认来源
字段不能通过批准出口
审核节点将其替换为“质保：待人工确认”
```

屏幕角落必须出现：

```text
演示错误，不代表实际产品政策
```

避免观众误把数字当成真实产品信息。

### Beat 18.4 — 人工核对与批准

讲师触发：“AI 可以帮你快，但不能替你确认事实。”

运动：

```text
来源完整的字段保持
待确认字段被保留为占位
不适合对外的字段被移出发布版本
HumanReviewNode 完成一次结构化核对
卡片获得“已审核”状态
```

批准状态不是夸张盖章动画，而是一条信号红确认线闭合卡片底部来源链。

卡片通过后进入边界内部的“可发布区”，但尚未连接任何外部发送端点。

### Beat 18.5 — 内容模块停靠，权限入口激活

讲师触发：“生成内容和自动执行，不是一个级别的风险。”

运动：

```text

内容入口显示为已完成
权限入口向前移动

```

章节标从 `03 / 04` 共享变形为 `04 / 04`。

### Beat 18.6 — 生成与执行分开

讲师触发：生成文案与自动发邮件、自动报价、自动操作系统不是同一风险层级。

画面将动作分成两层：

```text

外层：发送 / 报价 / 修改 / 操作
```

运动：

```text
内层动作停留在 SafetyBoundary 内部
外层动作位于边界外侧
两者之间出现 ActionConfirmGate
没有确认时，执行轨道保持断开
```

主屏出现：

```text
生成 ≠ 执行
```

### Beat 18.7 — 明确确认后才执行

讲师触发：“高风险动作必须有权限控制和人工确认。”

运动：

```text

确认卡显示：动作 / 对象 / 范围 / 负责人

执行轨道只在这一刻接通
邮件端点得到一次短促响应
```

不得表现为 AI 自己点击确认。

确认节点使用明确的人的责任标签：

```text
负责人确认
```

而不是抽象“系统批准”。

### Beat 18.8 — 四条边界形成完整操作回路

讲师触发：“安全不是为了吓大家，而是为了让企业敢用、会用、可控地用。”

```text

四条路径连接为一个完整安全回路
ProductStage、SourcePacket、OutputCards 位于回路内部

```

四条短句依次亮起：

```text

```

### Beat 18.9 — 安全边界准备变成诊断雷达

Scene 19 的主构图是一个非传统仪表盘：

```text
中心：ProductStage + SourcePacket + 已审核 OutputCard + ReviewNode
外环：由 SafetyBoundary 变形的 ScenarioRadar
四轴：上下左右或斜向四个诊断方向
候选场景：分布在环外，等待进入扫描区
标题：左上或左侧大面积留白
QRDock：默认隐藏，进入自测 Beat 后从右下展开
```

推荐四轴位置：

```text
上：重复最多
右：30 天可验证
下：资料最散
左：最缺模板
```

这样“30 天可验证”天然位于前进方向，便于 Scene 20 路线从右侧缺口展开。

## 6. Beat 设计

### Beat 19.1 — 安全边界展开为诊断雷达

讲师触发：“很多老板会问，我的企业到底该从哪里开始？”

运动：

```text
四个安全模块沿中心外移
模块外缘延伸成四条诊断轴
SafetyBoundary 外环扩大约 1.35 倍
内部安全节点缩为中心样板组的基础条件
四条安全标签淡出，轴标签位置保留
```

这不是删除安全，而是把安全作为场景判断的内层条件。

### Beat 19.2 — 四个判断方向被命名

讲师触发：不要先问哪个工具火，先问四件事。

四个 Beat 内的短动作可以连续由一次推进完成，也允许讲师逐项推进：

```text
重复最多：轴上出现循环任务痕迹
资料最散：轴上出现分散文件点
最缺模板：轴上出现空白结构框
30 天可验证：轴上出现一个可闭合结果环
```

每个方向只出现一个结构动作，不叠加大量图标。

### Beat 19.3 — 候选场景进入雷达外圈

讲师触发：不同企业，第一个场景不一样。

六个候选 token 进入外圈：

```text
销售话术
内容 / 视频
外贸回复
客服问答
会议 / SOP
安全规范
```

每个 token 携带最多三个条件标记：

```text
资料条件
负责人条件
审核条件
```

没有真实企业输入时，不显示数值评分。

### Beat 19.4 — 示例一：产品资料到销售话术

讲师触发：产品资料多、销售反复解释时，可以先做产品资料到销售话术。

运动：

```text
“销售话术”token 进入雷达
中心 SourcePacket 与其建立来源线
重复最多、资料最散、最缺模板三个轴出现结构响应
30 天可验证轴形成一个可见闭环
ProductStage 与一张销售输出卡短暂放大
```

屏幕右侧出现示例判断：

```text
已有产品资料
高频重复解释
结果容易被销售验证
```

这些是示例条件，不是自动打分。

### Beat 19.5 — 其他起点快速通过

讲师触发：制造、外贸、客服、行政和安全规范都可能成为起点。

采用同一个雷达容器切换候选，不重建界面：

```text
内容 / 视频：产品展示需求明显
外贸回复：询盘重复、响应慢
客服问答：问题高度重复
会议 / SOP：资料多、行动项易丢失
安全规范：员工已在用，但企业没有边界
```

每个候选停留约 450—700ms，由讲师推进；不自动轮播。

中心产品在非产品场景中降低对比度，但不消失，作为本课程的示例锚点。

### Beat 19.6 — 锁定“第一个场景”

讲师触发：“哪个场景最值得先跑，哪个结果最容易看见，哪个风险最需要先控。”

运动：

```text
所有候选 token 回到外圈
当前示例“产品资料 → 销售话术 / 内容样板”进入中心缺口附近
四个诊断轴向这个 token 收敛
环上形成一个明确的选中槽
```

主标题收束为：

```text
先选一个
最值得验证的场景
```

页面必须保留“示例判断”标签，避免暗示这是对现场企业的真实结论。

### Beat 19.7 — 现场自测入口展开

讲师触发：“接下来请大家用 3 分钟做一个自测。”

运动：

```text
雷达进入稳定低运动状态
QRDock 从右下展开
主二维码、短链和入口名称出现
四个扫描方向保持可读
候选场景退到外圈 40% 对比度
```

QRDock 文案：

```text
企业 AI 场景自测
约 3 分钟
```

手机表单承载六个完整问题；主屏不把六个问题全部展开。

讲师控制：

```text
T：启动 / 暂停 3 分钟计时器
Shift + T：重置计时器
```

计时器默认不启动。计时结束只做一次轻微结构提示，不播放警报音。

### Beat 19.8 — 从自测回到行动判断

讲师触发：“有明确场景、有基础资料、负责人愿意参与，就适合进一步诊断和验证。”

运动：

```text
QRDock 缩为右下小型入口，不完全消失
四轴重新提高对比度
中心选中场景 token 与 SourcePacket、负责人节点、审核节点建立四点关系
场景槽由虚线变为完整实线
```

四个进入条件短暂出现：

```text
真实场景
基础资料
负责人参与
可控边界
```

### Beat 19.9 — 扫描环从缺口展开为路线

讲师触发：“下一步不是继续听概念，而是拿真实资料跑一次。”

运动：

```text
ScenarioRadar 停止扫描
中心选中场景 token 进入接入环缺口
环的右侧分段从缺口处向前展开
圆形结构逐渐拉直为 ActionPath
四个诊断轴收拢为路线起点的判断节点
背景右侧开始出现暖白光面
```

Scene 20 的第一个节点 `今天` 在路径前方出现，但暂不展开内容。

## 11. 减少动态版本

- SafetyBoundary 直接切换为四轴雷达。
- 候选场景通过列表选中状态展示，不沿轨道移动。
- 扫描使用静态高亮，不旋转。
- QRDock 直接出现。
- ActionPath 由一条静态线替换外环，不执行大范围拉直动画。

## 12. Codex 实现提示

- 候选场景数据必须可配置，不在组件中写死业务逻辑。
- `ScenarioRadar` 不进行真实评分计算，除非后续接入明确规则。
- 计时器必须与 Scene 状态分离，后退 Scene 时暂停并保留或按配置重置。
- QRDock 的链接、标题和短链来自环境配置。
- 没有链接时只显示占位，不生成随机二维码。
- Scene 19.9 的环到线变形优先使用同一 SVG path 或可插值几何，避免两套图形交叉淡入。

## 13. 验收标准

- 四个诊断方向在 5 秒内可被观众读懂。
- 页面没有伪精确分数或自动推荐承诺。
- 六个候选场景属于同一套视觉系统。
- 自测时画面稳定、二维码清晰、无干扰动画。
- 选中场景能够无缝进入 ActionPath。
- 安全边界在诊断中仍作为内层条件存在。

# Scene 20 — 今天、30 分钟、3 天、3 个月

## 1. 叙事目的

把 Scene 19 选出的第一个场景变成一条可理解、可执行、不过度承诺的行动路径。

这幕不以“课程套餐”为主视觉，而以企业能力形成过程为主视觉：

```text
今天：看清是否值得试

3 天：用真实资料做出第一个样板
3 个月：把样板固化为团队能力
```

观众需要同时看见：

- 每个阶段的主要成果。
- 阶段之间的因果关系。
- 3 天与 3 个月的边界。
- 第一个样板如何从一次结果变成持续循环。

最终判断：

> 先判断，再验证，再固化。

ProductStage 不在这幕全程保持大尺寸。它在 Day 2 节点重新成为样板主角，在其他节点缩为场景卡内的产品缩略锚点。

## 11. 第四批统一验收标准

### 11.1 叙事

- 四条红线分别被理解为资料分级、工具准入、内容审核和权限确认。
- 安全被表现为让企业放心使用的操作规则，而不是阻止使用。
- 场景诊断回答“从哪里开始”，不回答“哪个工具最火”。
- 30 分钟、3 天、3 个月的成果和边界清楚。
- 最终 CTA 来自前面完整逻辑，而不是突然出现。
- Scene 01 的缺口在 Scene 21 得到明确闭合。

### 11.2 视觉

- Scene 16—18 保持同一个安全空间。
- SafetyBoundary 到 ScenarioRadar 到 ActionPath 到 CapabilityLoop 的几何同源关系清楚。
- ProductStage、SourcePacket、OutputCards 和 HumanReviewNode 贯穿最后五幕。
- Scene 21 的产品穿字构图具有静态拍照质量。
- CTA 与 Q&A UI 不破坏终幕视觉层级。

### 11.3 内容与责任边界

- 所有敏感资料示例均为虚构或脱敏。
- 不展示真实工具安全排名。
- 不把演示错误误认为产品事实。
- 内容批准与执行授权彼此独立。
- 诊断不输出伪精确分数。
- 3 天与 3 个月不使用保证式结果表述。
- 二维码、名额、日期和链接必须来自业务方正式确认。

### 11.4 交互

- 每个 Beat 可前进、后退和重置。
- 资料遮罩、工具连接、审核状态和权限状态可准确恢复。
- Scene 19 计时器可启动、暂停、重置，且不阻塞演示导航。
- Scene 20 可直接跳到任意阶段并正确建立前置状态。
- Scene 21 Q&A 可通过 Q、1—6、方向键和 Esc 操作。
- 刷新页面能恢复当前 Scene、Beat、CTA 入口和 Q&A 状态。

### 11.5 性能与可靠性

- 所有 P0 素材本地可用，离线不影响主流程。
- QR 由本地资产提供，断网仍可显示短链和编号。
- Scene 18 的内容卡、审核节点和权限节点不触发真实外部动作。
- Scene 19 扫描动画不会长期占用高帧率资源。
- Scene 21 稳定停留时降低非必要渲染频率。
- Reduced Motion 模式保持完整叙事、扫码和 Q&A 能力。

```text
投影仪低对比模式
```

## 12. 本批锁定，不再继续发散

1. Scene 17 只讲资料与工具，Scene 18 只讲内容与权限。
2. 四条红线使用四种不同动作，不使用四张相同图标卡。

12. 最终缺口由真实场景 / 样板填补，不由工具 Logo 或抽象 AI 图标填补。
