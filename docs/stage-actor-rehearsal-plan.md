# 舞台演员排练总表 V1

## 这一步先解决什么

当前先暂停继续叠加视觉、动画和滚动效果。问题的根源不是某个组件样式不够好，而是舞台逻辑还没有真正成立。

现在的旧实现里，很多视觉对象仍然按 Beat 或 frameKind 各自生成。观众看到的效果就像同一个演员在一场戏里反复上场，或者还没退场就出现第二个自己。后续必须改成舞台剧方法：

1. 先定演员。
2. 再定每个演员负责哪一段戏。
3. 再定每个演员的入场、保持、让位、退场。
4. 最后才安排场景、镜头、灯光、动画和滚动观感。

本文件只做整理和推进合同，不修改旧生产逻辑，不新增依赖，不实现新动画，不创建新页面。

## 最终目标

最终不是 144 页 PPT，也不是普通网页长滚动，而是一场由讲师控制的全屏舞台演示：

- 21 个 Scene 是五幕戏里的场景变化。
- 144 个 Beat 是导演 cue，不是 144 张新页面。
- 同一个语义对象只允许有一个主身体。
- 一个演员只在首次出现时入场，只在使命结束时退场。
- 中间 Beat 只能移动、缩放、换灯光、换状态、换主次，不能反复重新生成。
- 右侧控制器属于讲师后台，演示时默认折叠，不应成为观众主画面。

## 舞台硬规则

### 1. 同一个演员只有一个主身体

同一个演员可以有不同状态，例如大尺寸、压缩尺寸、背景尺寸、强调状态，但不能同时由多个组件画出多个主体。

例子：

- 产品主体只能是同一个 `actor.product-stage`。
- 输出卡片只能是同一个 `actor.output-cards`，`frozen`、`review`、`approved` 是状态，不是三套组件。
- CTA 只能是同一个 `actor.cta-dock`，compact 和 expanded 是状态，不是两个 CTA。

### 2. 每个 Beat 只有四种生命周期

| 状态 | 含义 | 允许动作 | 禁止动作 |
| --- | --- | --- | --- |
| `enter` | 上一 Beat 不在场，这一 Beat 首次在场 | 入场、显现、路径首次绘制 | 同一连续段里重复入场 |
| `hold` | 上一 Beat 已在场，这一 Beat 继续在场 | 移动、变形、强调、换灯光、换角色主次 | 从 0 opacity 重新出现 |
| `exit` | 这一 Beat 是最后一次在场 | 退场、收束、让位 | 提前消失后马上又进来 |
| `off` | 不在场 | 完全不可见、不可交互 | 残留透明层、残留可点击层 |

验收句：

> 一个演员站在舞台上时，只能继续表演，不能反复上场。

### 3. Scene 是布景，不是新页面

Scene 只负责改变灯光、构图、景深、主次关系。一个跨 Scene 持续存在的演员不能因为换了 Scene 就重新入场。

### 4. Beat 是 cue，不是幻灯片

Beat 只能告诉导演：

- 谁在场。
- 谁是主角。
- 谁退到背景。
- 谁做一次主运动。
- 谁保持稳定。
- 谁准备退场。

## 当前真正的问题点

### 问题 1：中段演员还没有完全归一

已经比较稳定的演员：

- 接入环
- 判断问题
- 四本账圆盘
- 产品主体
- 人工审核节点
- 负责人确认门
- 行动路径
- CTA

仍然最容易叠屏的演员：

- 资料包
- 参数到利益转译链
- 输出卡片系统
- 安全边界
- 场景诊断雷达

下一轮如果要动代码，必须优先处理这五个演员，而不是继续增加动画或新视觉层。

### 问题 2：路线层太多

现在历史上累积过多个“路线/滚动/连续性”层。即使已经有部分被隐藏，后续仍必须明确：

- 观众可见路线只保留一套。
- 其他路线层要么成为背景景深，要么成为开发辅助，要么删除。
- 不允许多套路线、多个主舞台、多个主视觉同时抢信息。

### 问题 3：自由滚动感和项目合同存在边界

你希望像参考站一样有自由滚动感，这个方向成立。但当前 `AGENTS.md` 仍要求：

- 演示模式由键盘/控制器驱动。
- 不接入 smooth scrolling。
- 不使用点击次数或滚动像素累计 transform。

所以短期可做的是：

- 视觉上做成连续舞台。
- 滚轮/触控板可以作为上一 Beat / 下一 Beat 的输入。
- 状态仍然由 Beat 的绝对目标决定。

如果要真正变成原生自由滚动网页，需要先单独批准修改项目架构合同。

## 后续推进顺序

### WP-24A：演员合同冻结

目标：

- 以本文件为准，确认演员表、进出场和主角接力。
- 统一命名，不再一会儿叫 output-system，一会儿叫 output-cards。
- 确认 CTA 入场时机和四本账退场方式。

验收：

- 每个演员有明确 `actorId`。
- 每个演员有首次入场和最后退场。
- 每个演员只有一个主身体归属。
- 人工确认后，才允许进入代码改造。

### WP-24B：中段演员归并

目标：

- 把资料包、转译链、输出卡片、安全边界、场景雷达收进持久演员层。
- 旧 frame 分支不再画这些演员的第二套身体。

验收：

- `10.x -> 19.x` 不再出现同一个资料包/输出卡/安全边界多副本叠加。
- 连续 Beat 中只有第一次是 `enter`，中间都是 `hold`。
- 退场后没有可见残影或可点击残影。

### WP-24C：观众路线层裁剪

目标：

- 只保留一套观众可见路线系统。
- 其他路线层降级为背景、开发辅助或删除。
- 右侧讲师控制器继续默认折叠。

验收：

- 1366x768 下主角一眼可读。
- 观众主屏不长期出现右侧控制面板。
- 画面不再像多套组件叠在一起。

### WP-24D：导演运行时重排

目标：

- 动画 runtime 只读 actor lifecycle。
- `enter` 播入场。
- `hold` 播移动、强调、morph。
- `exit` 播退场。
- `off` 不留残影。

验收：

- `03.5` 接入环不重新入场。
- `09.2` 产品不重新 reveal。
- `18.8` 审核和确认不重新入场。
- `20.10` 行动路径不重画。
- `21.8` CTA 不循环干扰终幕。
