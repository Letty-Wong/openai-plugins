# 舞台演员归并与进出场表 V1

## 这份文档解决什么

当前画面混乱的核心原因不是某个组件做得不好，而是同一个语义对象被不同 Beat、不同视觉层、不同 frame 分支重复画出来。

从舞台剧角度看，这相当于同一个演员在场上还没退场，旁边又出现了另一个同名演员，或者演员在连续表演时每一幕都重新上场一次。

后续整改必须先遵守这条规则：

> 同一个演员只能有一个主身体。连续多个 Beat 出现时，第一次是入场，中间是保持和表演，最后一次才退场。

## 四种生命周期

| 状态 | 解释 | 可以做 | 不可以做 |
| --- | --- | --- | --- |
| `enter` | 上一 Beat 不在场，这一 Beat 首次在场 | 入场、显现、路径首次绘制 | 同一连续段里反复从 0 入场 |
| `hold` | 上一 Beat 已在场，这一 Beat 继续在场 | 移动、变形、强调、换灯光、换主次 | 重建一个新 DOM 当作同一对象 |
| `exit` | 这一 Beat 是最后一次在场 | 退场、缩小、让位、淡出 | 提前消失后马上又进来 |
| `off` | 不在场 | 完全不可见 | 残留透明层、残留可点击层、残留 ghost |

## 下一步实现前的验收问题

继续动代码前，建议先人工确认下面五件事：

1. CTA dock 是从 `19.x` compact 入场，还是 `21.7` 才首次入场？
2. 输出系统的首次入场是 `12.x`，还是只从 `15.8` 输出冻结开始？
3. 四本账圆盘在 `08.7` 后是完全退场，还是退为产品背后的经营坐标？
4. 全局路线最终保留哪一套观众可见系统，其余是否全部隐藏或删除？
5. 是否要修改 `AGENTS.md`，允许真正自由滚动；如果不改，短期仍应保持 Beat 控制，只把视觉做成连续滚动感。

## 当前推进建议

下一步不要继续加动画，也不要继续叠新视觉层。

正确顺序是：

1. 人工确认本表的演员身份和进出场。
2. 逐个把旧 frame 分支里的重复主身体迁入 `PersistentActorLayer`。
3. 每迁一个演员，就加测试确认旧分支不再渲染第二套身体。
4. 最后再调整动画 runtime，让它只按 `enter` / `hold` / `exit` 播放。
