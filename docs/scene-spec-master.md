## 0. 文档用途与权威顺序

本文件把四批分镜合并为一份统一总控规格。它解决的不是“网页要有哪些页面”，而是以下五个工程问题：

1. 21 幕如何组成一条连续镜头，而不是 21 张动画海报。
2. 144 个讲师节拍如何前进、后退、跳转和恢复。
3. 同一个接入环、产品、资料包和业务卡如何跨幕持续存在。
4. 哪些内容已经锁定，哪些必须由企业确认，哪些只允许占位。
5. Codex 实现时，哪些规则不得被局部页面自行改写。

### 权威顺序

发生冲突时，按以下顺序处理：

1. **本总版**：视觉、交互、对象生命周期和工程约束的最高优先级。
2. **原始讲师逐字稿**：完整语义、课程口径、时长与讲师备注来源。
3. **《花洒产品演示：素材与内容准备清单 V1》**：产品素材、事实状态和生产规格。
4. **四批分镜文件**：保留为设计过程档案；其中与本总版冲突的命名由本总版覆盖。
5. **后续 `content/*.ts` 配置**：代码阶段形成的运行时单一数据源，但不得改变本规格的叙事功能。

### 已锁定的项目定义

> 这是一个由讲师控制的沉浸式演示网页：固定视觉舞台 + 连续对象转场 + 21 个 Scene + 144 个 Beat + 隐藏讲师备注。

它不是长文章，不是普通 PPT 网页化，也不是让用户自由滚动触发所有演示的营销落地页。主演示首先服务于 1920 × 1080 的线下投屏。

## 1. 叙事总线

整场课的视觉叙事只有一条主线：

```text
一个尚未闭合的 AI 接入环
→ 变成时代轨道
→ 变成经营圆盘
→ 变成资料转换孔径
→ 变成安全边界
→ 变成诊断雷达
→ 变成行动路线
→ 被第一个真实业务样板闭合为企业能力回路
```

课程内容形成六章：

```text
做出判断
→ 看四本账
→ 用真实产品证明
→ 建立安全边界
→ 找到第一个场景
→ 从样板形成能力
```

视觉高潮位于 Scene 09—16；情绪转折位于 Scene 15.7—16.3；最终闭环位于 Scene 20.10—21.3。

## 2. Scene + Beat 控制模型

### Scene

Scene 是稳定的叙事空间。进入一个 Scene 后，背景、核心对象、构图和主要语义不应被随意重建。

### Beat

Beat 是讲师控制的局部变化。一个 Beat 应当只完成一个清晰动作，例如：

- 接入环被描绘出来；
- 一张事实卡穿过转换孔径；
- 一组卡片重排到部门轨道；
- 内容审核通过，但执行仍停靠等待确认。

### 编号合同

- Scene ID 固定为 `scene-01` 至 `scene-21`。
- Beat ID 固定为 `01.1` 至 `21.9`，共 144 个。
- Q&A 是 Scene 21 的子模式，不创建 Scene 22。
- 后续可调整屏幕短句，但不能复用、删除或重新编号既有 ID；若确需插入，只能追加如 `11.6a` 的临时设计 ID，正式版本再统一升级版本号。

## 4. 统一视觉系统

### 4.1 风格比例

- **70% 工业电影感**：近黑空间、信号红、精确轴向运动、环形门户、章节编号、机械停靠。
- **30% 编辑与产品戏剧性**：巨型中文、产品穿字、不对称构图、前后遮挡、共享元素变形。

参考网站只提供视觉机制，不复制品牌、模型、插画、字体、照片或文案。

### 4.2 三个视觉世界

| 世界 | Scene | 背景 | 核心对象 | 运动性格 |
|---|---|---|---|---|
| 判断与压力 | 01—05 前半 | 近黑、深红、金属灰 | 接入环、时间轨道、企业路径 | 精确、轴向、克制 |

## 6. 五类主转场与辅助语法

全站只能使用以下五类主转场：

1. **接入环门户**：环与下一场景的遮罩同步开合。
2. **持续主角转场**：同一个产品、资料包或几何对象跨幕移动和变形。
3. **共享容器变形**：卡片、海报、视频工作台和业务文档保持同一容器身份。
4. **方向性切割**：方向与语义一致；开源向外、节流向内、提效向前、沉淀向下、安全门关闭、路线向前展开。
5. **文字与产品遮挡**：仅用于 Scene 01、09 和 21 等少数关键节点。

辅助语法包括：

- 共享元素重排；
- 图层差速；
- 资料字段遮罩；
- 人工审核停靠；
- 权限确认门；
- 短暂冻结。

禁止将整屏淡入淡出作为默认转场；必要时只可用于降级或极短的错误恢复。

### 动效纪律

每个 Beat：

```text
1 个主要运动
+ 1 个辅助运动
+ 1 个可选环境循环
```

建议参数：

```text
普通进入：0.65—1.15s
章节门户：0.9—1.5s
共享容器：0.8—1.2s
卡片重排：0.7—1.3s
安全门：0.5—0.85s
扫描：1.2—1.8s
终幕闭合：1.1—1.6s
冻结：80—160ms 内停止循环
```

讲解稳定态无限延长。环境循环位移 2—8px、旋转 0.5—1.5°、缩放不超过 1%，周期 3—6 秒。

### 7.2 导航规则

## 9. 内容诚信与安全状态

产品与业务数据统一使用：

```ts
type ContentStatus =
  | "VERIFIED"
  | "APPROVED"
  | "PLACEHOLDER"
  | "DO_NOT_USE";
```

- `VERIFIED`：有正式资料支持。
- `APPROVED`：业务方确认可以对外表达。
- `PLACEHOLDER`：尚未确认，主屏必须明确显示“待人工确认”。
- `DO_NOT_USE`：敏感或禁止公开，不进入观众主屏。

以下内容不得由前端或 AI 自行补全：

- MOQ、价格、交期、质保；
- 恒温精度、节水比例、寿命；
- 认证、专利和测试结果；
- 工具安全排名；
- 企业诊断精确分数；
- 课程名额、截止日期和保证式结果。

安全示例只使用公开、虚构或脱敏数据。内容批准与执行授权必须为两个独立状态。

## 11. 性能、离线与可访问性

### 性能

- 第一版以 SVG、DOM、CSS mask、GSAP 和 2.5D 产品图为主。
- 不把 Three.js / GLB 设为阻塞项；引入前必须证明 2.5D 版本已完整成立。
- 同时可见的业务卡控制在 12—16 张以内。
- 预解码下一幕关键产品图，尤其是 Scene 15 → 16 的 RED 资产。
- 隐藏层停止滤镜、粒子与持续合成；离场后移除不必要的 `will-change`。
- Scene 21 稳定停留时降低非必要更新频率。

### 离线与恢复

- 所有 P0 视觉资产本地打包。
- 主流程不调用外部 API。
- 二维码本地提供，并同时显示短链／编号。
- 图片失败时回退到同注册剪影或明确占位，不让主舞台空白。
- 页面刷新后恢复 Scene、Beat、备注、Q&A 与 CTA 状态。

### 减少动态

`prefers-reduced-motion` 或手动 M 模式下：

- 不使用长距离透视移动、路径追踪和连续旋转。
- 共享元素直接切到稳定终态，配合 150—250ms 淡入或无动画。
- 仍完整保留资料分级、人工审核、权限确认、二维码和 Q&A。
- 不因减少动画而删除关键逻辑。

### 语义与键盘

- 主要文字必须存在于 HTML，不绘制进 Canvas。
- 控制按钮可聚焦，并具有可见焦点。
- 讲师 HUD 与观众内容建立正确的 ARIA 隔离。
- 全屏失败、快捷键冲突和浏览器 UI 均有可操作回退。

## 13. 已消除的规则冲突

1. **Scene 16 归属**：虽然在第三批文件中设计，叙事归属第四章“安全”，与 Scene 17—18 连续。
2. **经营盘与接入环**：`AccountDial` 是接入环的经营角色，不是第二套全局圆环。
3. **业务源点与资料包**：`BusinessSeed` 统一为 `SourcePacket` 的早期状态。
4. **工作卡与输出卡**：统一进入 `ArtifactLayer` 注册表，用 `kind` 区分。
5. **安全环、雷达、路线、能力环**：共享几何与路径 ID，不分别重建。

7. **3D 路线**：V1 固定为 2.5D 优先；GLB 为后续增强，不阻塞开发。
8. **CTA**：Scene 21 同时只显示一个主二维码；多个入口通过切换呈现。

10. **动画状态**：全部使用绝对目标值，不使用累计 transform。
11. **内容状态**：统一为 VERIFIED / APPROVED / PLACEHOLDER / DO_NOT_USE。
12. **自动化边界**：内容批准与执行授权必须分离。

## Scene 07 — 节流与提效：减少重复，缩短路径

### 1. 叙事目的

把“节流”和“提效”设计成一台可见的工作机制：

```text
节流：将重复分支收拢
提效：将工作路径缩短
人的角色：从每次从零写，移动到审核、判断、优化和确认
```

这一幕必须明确：

- 不删除员工。
- 不跳过资料。
- 不跳过人工审核。
- 不把 AI 初稿直接当最终结果。

### 2. 屏幕文案

```text

```

```text
提效
```

```text

```

```text

→
审核 / 判断 / 优化 / 确认
```

辅助句：

```text
人不消失
工作重心改变
```

### 3. 构图

场景转换为横向工作台：

```text

审核区：x 64—76
输出区：x 82—94

重复任务轨道 y：22—72

巨型“提效”：右后景
```

BusinessSeed 位于输入区，中央开放弧压缩为一座纵向流程门。

工作台不模拟真实软件界面，而是以卡片、轨道、门和状态标记构成。

主运动：重复卡片堆积。

辅助运动：轨道轻微下沉，表现负担增加。

#### Beat 07.3 — 节流：重复路径收拢

讲师触发：“真正的节流，是减少低价值重复劳动。”

运动：


主运动：向内压缩。

辅助运动：后景“节流”提高至 22% 对比度。

#### Beat 07.4 — 生成的是初稿

讲师触发：“基于资料快速生成初稿。”

运动：

```text

```

流程门内部只做一次短暂的线性扫光，不使用魔法粒子或复杂 AI 大脑动画。


这里仅建立“人工审核不可跳过”，具体安全红线留到 Scene 16—18。

#### Beat 07.6 — 提效：工作路径缩短

讲师触发：“员工从从零写，变成审核、判断、优化、确认。”

运动：

```text
旧路径以灰色残影保留在上方

资料 → 初稿 → 审核 → 确认
旧路径的多个中间节点向内收缩
后景“提效”从右侧进入
主屏文字完成切换：
从零写 → 审核 / 判断 / 优化 / 确认
```

主运动：路径缩短。

辅助运动：输出槽向左靠近审核门，减少空间距离。

#### Beat 07.7 — 人的工作重心改变

讲师触发：“AI 不是完全自动替代人，而是高效率助理。”

运动：

```text
一个抽象的负责人标记从空白文档起点移动到审核门
空白文档起点降低对比度
审核门、判断标记和最终确认提高对比度
主屏出现：
人不消失
工作重心改变
```

不使用人物插画，负责人标记可以是一枚带首字母或圆点的身份节点。

#### Beat 07.8 — 好结果不离开系统

讲师触发：准备转入“沉淀能力”。

运动：

```text
三张审核通过的卡片没有飞向屏幕外
它们沿一条向下轨道进入舞台下方
流程门与审核门缩小并合并
底部出现一个分层能力核心的轮廓
后景“节流 / 提效”同时退到低对比度
```

### 7. 结束帧

- `IntegrationRing` 继续使用全局实例。
- 负责人节点是流程责任的视觉锚点，不代表自动化系统中心。
- 花洒剪影与 Scene 09 实体图必须共享同一 wrapper，保证无缝替换。
- 四张准备卡在 Scene 09/10 仍可复用，不要在 08.7 后销毁。

### 13. 验收标准

- “沉淀”表现为审核后的结果回流，不是简单文件堆叠。
- 个人使用与企业接入的差别无需长文也能读懂。
- AI native 画面没有技术架构图感。

```text
中栏 x 40—60：接入环转换孔径
右栏 x 66—95：客户利益卡与场景标签
```

产品部分裁切在左侧，保持 65% 以上可识别；接入环是画面中心；右侧留出较大空白以容纳利益卡。

#### Beat 11.1 — 事实进入转换孔径

```text

```

```text
家庭 / 酒店
```

事实卡与利益卡不是两个对象交叉淡入，而是同一个容器在环内完成宽度、排版和内容状态切换。

#### Beat 11.3 — 第二组：防烫设计

讲师触发：老人和小孩的使用安全。

运动：

```text

```

#### Beat 11.4 — 第三组：硅胶出水嘴

```text

```

禁止写“永不堵塞”。

#### Beat 11.5 — 第四组：铜主体或实际主体材质

讲师触发：耐用和质感。

运动：

```text

生成耐用 / 质感方向利益卡
场景标签：家装 / 工程
```

```text

```

并保留流程演示，不显示虚构客户利益。

#### Beat 11.6 — 形成一份利益母版

讲师触发：“这一步解决的不是漂亮文案，而是销售表达问题。”

```text
重排为 BenefitMaster

接入环向右侧 ContentShell 接口移动
```

主屏判断：

```text

而是没有把卖点说成客户利益
```

## Scene 17 — 资料与工具：先分级，再接入

本幕不要求观众记住复杂制度，只需要带走：

> 哪些资料可以用，哪些需要脱敏，哪些禁止进入；企业资料只进入可确认的工具。


```text

脱敏
禁止上传
```

### 6. Beat 设计

#### Beat 17.1 — 资料入口展开为三级门

讲师触发：“不是所有资料都能直接给 AI。”


- `脱敏`门中间增加一层可移动遮罩。

#### Beat 17.2 — 公开资料直接进入

## Scene 18 — 内容与权限：生成可以快，发布和执行必须确认

### 1. 叙事目的

完成安全章节的后两条红线，并把 AI 的角色明确限定为：

```text
可以起草
可以整理
可以建议
不能替企业确认事实
不能在没有授权的情况下执行高风险动作
```

这幕要让观众看到两个不同风险层级：

1. 内容是否可以对外发布。
2. 系统动作是否可以真正执行。

内容审核与权限确认不能合并成同一个“人工按钮”。前者核对事实与表达，后者决定是否发生真实业务动作。

最终判断：

> AI 可以帮你快，但不能替你确认事实，也不能越过权限直接执行。




```text

权限红线
```

```text
生成 ≠ 执行
```

动作层级：

```text
起草
发送
报价
操作
```

最终停留句：

```text
生成可以快
发布和执行必须确认
```

辅助句：

```text
边界不是为了少用，而是为了放心用
```

### 3. 构图

```text

上方：工具准入模块
中部：ProductStage 与 SourcePacket
右侧或右下：内容入口激活
```

```text

```

```text

```

画面要清楚表现：有内容批准，不代表自动获得执行权限。

```text
主标题与章编号
```

外部动作端点只用抽象结构表示：邮件、报价、系统、文件，不仿制真实业务系统界面。

### 5. 起始帧

- 资料与工具模块已稳定。
- 内容入口当前激活。
- 一张来自 Scene 15 的业务输出卡仍位于边界内部。
- 产品和资料包保持可见。
- 左侧主标题仍为“先分级，再接入”，即将退为背景判断。

### 6. Beat 设计

#### Beat 18.1 — 内容入口展开为审核路径

讲师触发：“AI 生成内容可以作为初稿，但对外发布前必须审核。”

运动：

```text
内容入口向右展开
原 OutputCard 从五部门轨道中被取出
卡片保持同一个 ID，进入 HumanReviewNode 左侧
SourcePacket 与卡片之间的来源线重新亮起
路径上依次出现：初稿 / 核对 / 修订 / 批准
```

主标题切换为：

```text
生成的是初稿
```

#### Beat 18.2 — 需要核对的字段被看见

讲师触发：产品参数、价格、质保、承诺、法律财税、客户案例和竞品比较不能直接发布。

运动：

```text
OutputCard 内部不可信或待确认字段被逐项圈出
参数 / 价格 / 质保 / 承诺 / 案例五个字段标记浮到审核节点上方
每个字段连接回 SourcePacket 的对应来源或 PLACEHOLDER
```

没有来源的字段显示：

```text
待人工确认
```

禁止自动生成一个看似真实的替代值。

#### Beat 18.3 — 错误承诺被阻止

讲师触发：AI 不能替企业确认事实。

使用一个明确标注为“演示错误”的示例：

```text
质保：5 年？
```

视觉处理：

```text
该字段以虚线和问号进入审核节点
SourcePacket 中没有对应已确认来源
字段不能通过批准出口
审核节点将其替换为“质保：待人工确认”
```

屏幕角落必须出现：

```text
演示错误，不代表实际产品政策
```

避免观众误把数字当成真实产品信息。

#### Beat 18.4 — 人工核对与批准

讲师触发：“AI 可以帮你快，但不能替你确认事实。”

运动：

```text
来源完整的字段保持
待确认字段被保留为占位
不适合对外的字段被移出发布版本
HumanReviewNode 完成一次结构化核对
卡片获得“已审核”状态
```

批准状态不是夸张盖章动画，而是一条信号红确认线闭合卡片底部来源链。

卡片通过后进入边界内部的“可发布区”，但尚未连接任何外部发送端点。

#### Beat 18.5 — 内容模块停靠，权限入口激活

讲师触发：“生成内容和自动执行，不是一个级别的风险。”

运动：

```text
HumanReviewNode 缩小并停靠到 SafetyBoundary 右侧
内容入口显示为已完成
权限入口向前移动
一条尚未接通的执行轨道从批准卡延伸到外部动作端点
```

章节标从 `03 / 04` 共享变形为 `04 / 04`。

#### Beat 18.6 — 生成与执行分开

讲师触发：生成文案与自动发邮件、自动报价、自动操作系统不是同一风险层级。

画面将动作分成两层：

```text
内层：起草 / 建议 / 整理
外层：发送 / 报价 / 修改 / 操作
```

运动：

```text
内层动作停留在 SafetyBoundary 内部
外层动作位于边界外侧
两者之间出现 ActionConfirmGate
没有确认时，执行轨道保持断开
```

主屏出现：

```text
生成 ≠ 执行
```

#### Beat 18.7 — 明确确认后才执行

讲师触发：“高风险动作必须有权限控制和人工确认。”

运动：

```text
一张已审核邮件初稿到达 ActionConfirmGate
确认卡显示：动作 / 对象 / 范围 / 负责人
讲师推进后，确认结构闭合
执行轨道只在这一刻接通
邮件端点得到一次短促响应
```

不得表现为 AI 自己点击确认。

确认节点使用明确的人的责任标签：

```text
负责人确认
```

而不是抽象“系统批准”。

#### Beat 18.8 — 四条边界形成完整操作回路

讲师触发：“安全不是为了吓大家，而是为了让企业敢用、会用、可控地用。”

运动：

```text
权限模块停靠到 SafetyBoundary 最后一侧
资料 / 工具 / 内容 / 权限四个模块全部形成稳定结构
四条路径连接为一个完整安全回路
ProductStage、SourcePacket、OutputCards 位于回路内部
HumanReviewNode 与 ActionConfirmGate 成为持续节点
```

四条短句依次亮起：

```text
资料先分级
工具先准入
内容先审核
执行先确认
```

#### Beat 18.9 — 安全边界准备变成诊断雷达

讲师触发：“边界清楚以后，下一步不是全面改造，而是选对第一个场景。”

运动：

```text
四个边界模块沿圆周重新校准到四个等距方向
模块内部细节收拢为四个简洁结构片
中心接入环出现一个明确缺口
ProductStage、SourcePacket、ReviewNode 和一张已审核 OutputCard 缩到中心样板组
外层背景开始由纯近黑过渡为有深度的深灰空间
```

四个安全标签开始弱化，为 Scene 19 的四个诊断方向预留位置。

- 资料、工具模块不消失，成为完整安全回路的一部分。
- Scene 15 的 OutputCard 直接作为审核对象。
- SourcePacket 提供事实来源，不重新创建资料卡。

#### 进入 Scene 19

- 四个安全模块旋转并伸展为四个诊断轴。
- 中心样板组保持原坐标与身份。
- HumanReviewNode 不消失，缩为候选场景所需“审核条件”的一部分。
- 接入环缺口成为 ActionPath 后续展开的起点。

### 9. 所需素材

#### P0

- HumanReviewNode SVG / DOM 结构。
- 输出初稿卡、已审核卡和待确认字段。
- 来源连接线。
- `演示错误`状态样式。
- ActionConfirmGate。
- 邮件、报价、系统、文件四个抽象动作端点。
- 负责人确认卡。
- 四条边界汇总结构。

#### 内容要求

- 错误示例必须明确标注为演示。
- 不展示真实客户、价格或产品承诺。
- 发布与执行状态必须可被讲师控制，不自动推进。

### 10. 讲师控制点

```text
18.1 “生成内容可以作为初稿”
18.2 列出必须核对的字段
18.3 展示没有来源的承诺如何被阻止
18.4 “AI 不能替企业确认事实”
18.5 从内容风险转向执行风险
18.6 “生成和执行不是一个级别”
18.7 展示负责人确认
18.8 总结四条红线
18.9 “下一步是选对第一个场景”
```

### 11. 减少动态版本

- 初稿、审核稿和批准稿使用同一位置内容切换。
- 字段核对以描边状态变化完成。
- 执行轨道在确认前后切换断开 / 接通状态。
- 四条边界模块直接排成完整回路，不执行大范围旋转。
- Scene 19 进入时使用 300ms 结构替换。

### 12. Codex 实现提示

- `HumanReviewNode` 和 `ActionConfirmGate` 必须是两个组件和两个状态。
- `approvedContent` 不应自动将 `executionAuthorized` 设为 true。
- 错误示例数据单独存放，带 `demoOnly: true`。
- 所有发布 / 执行动作只是视觉演示，不触发真实邮件、报价或系统操作。
- 负责人确认必须由显式 Beat 推进，不能自动计时。
- 四条边界完成状态应序列化，刷新时可重建。

### 13. 验收标准

- 观众能理解“初稿、审核、批准”的关系。
- 未确认字段不能进入已批准内容。
- 观众能清楚区分内容发布与真实执行。
- AI 不被表现为自行获得权限。
- 四条边界在结束帧形成一套完整操作系统，而不是四张散卡。
- Scene 18 → 19 的边界到雷达转场不依赖整屏淡出。

## Scene 19 — 第一个场景，从哪里开始？

### 1. 叙事目的

把观众从“知道边界”带到“能够选择第一个业务场景”。

这幕不提供一个通用答案，而是建立四个判断方向：

```text
哪个环节重复最多？
哪些资料最散？
哪个岗位最缺模板？
哪个结果最容易在 30 天内验证？
```

同时展示多个企业可能的起点，并明确：

> 不先问哪个工具最火，先找一个高频、可控、可验证的真实场景。

Scene 19 还承担现场 3 分钟自测的演示控制，因此必须有稳定的讲解状态、二维码状态与可选计时器，不让背景动画干扰观众扫码。

### 2. 屏幕文案

主标题：

```text
第一个场景
从哪里开始？
```

四个扫描方向：

```text
重复最多
资料最散
最缺模板
30 天可验证
```

候选场景：

```text
产品资料 → 销售话术
产品资料 → 内容 / 视频脚本
外贸询盘 → 英文回复模板
客户问题 → 问答库
会议 / 流程 → SOP
先建轻量安全规范
```

判断句：

```text
先选一个
最值得验证的场景
```

自测提示：

```text
3 MIN SELF-CHECK
扫二维码，完成企业场景自测
```

辅助句：

```text
结果需结合真实资料进一步诊断
```

### 3. 构图

Scene 19 的主构图是一个非传统仪表盘：

```text

外环：由 SafetyBoundary 变形的 ScenarioRadar
四轴：上下左右或斜向四个诊断方向
```

推荐四轴位置：

```text
上：重复最多
右：30 天可验证
下：资料最散
左：最缺模板
```

这样“30 天可验证”天然位于前进方向，便于 Scene 20 路线从右侧缺口展开。

### 4. 图层结构

```text

下一幕路径缺口
```

候选场景使用文字 token 和小型关系图，不使用六张不同风格的业务插画。

### 5. 起始帧

继承 Scene 18.9：

- 四条边界模块位于四个等距方向。
- 中心保留产品、资料、已审核输出和人工节点。
- 接入环有明确缺口。
- 背景从近黑向深灰空间过渡。
- 标题“生成可以快，发布和执行必须确认”正在退为背景判断。

### 6. Beat 设计

#### Beat 19.1 — 安全边界展开为诊断雷达

讲师触发：“很多老板会问，我的企业到底该从哪里开始？”

运动：

```text
四个安全模块沿中心外移
模块外缘延伸成四条诊断轴
SafetyBoundary 外环扩大约 1.35 倍
内部安全节点缩为中心样板组的基础条件
四条安全标签淡出，轴标签位置保留
```

这不是删除安全，而是把安全作为场景判断的内层条件。

#### Beat 19.2 — 四个判断方向被命名

讲师触发：不要先问哪个工具火，先问四件事。

四个 Beat 内的短动作可以连续由一次推进完成，也允许讲师逐项推进：

```text
重复最多：轴上出现循环任务痕迹
资料最散：轴上出现分散文件点
最缺模板：轴上出现空白结构框
30 天可验证：轴上出现一个可闭合结果环
```

每个方向只出现一个结构动作，不叠加大量图标。

#### Beat 19.3 — 候选场景进入雷达外圈

讲师触发：不同企业，第一个场景不一样。

六个候选 token 进入外圈：

```text
销售话术
内容 / 视频
外贸回复
客服问答
会议 / SOP
安全规范
```

每个 token 携带最多三个条件标记：

```text
资料条件
负责人条件
审核条件
```

没有真实企业输入时，不显示数值评分。

#### Beat 19.4 — 示例一：产品资料到销售话术

讲师触发：产品资料多、销售反复解释时，可以先做产品资料到销售话术。

运动：

```text
“销售话术”token 进入雷达
中心 SourcePacket 与其建立来源线
重复最多、资料最散、最缺模板三个轴出现结构响应
30 天可验证轴形成一个可见闭环
ProductStage 与一张销售输出卡短暂放大
```

屏幕右侧出现示例判断：

```text
已有产品资料
高频重复解释
结果容易被销售验证
```

这些是示例条件，不是自动打分。

#### Beat 19.5 — 其他起点快速通过

讲师触发：制造、外贸、客服、行政和安全规范都可能成为起点。

采用同一个雷达容器切换候选，不重建界面：

```text
内容 / 视频：产品展示需求明显
外贸回复：询盘重复、响应慢
客服问答：问题高度重复
会议 / SOP：资料多、行动项易丢失
安全规范：员工已在用，但企业没有边界
```

每个候选停留约 450—700ms，由讲师推进；不自动轮播。

中心产品在非产品场景中降低对比度，但不消失，作为本课程的示例锚点。

#### Beat 19.6 — 锁定“第一个场景”

讲师触发：“哪个场景最值得先跑，哪个结果最容易看见，哪个风险最需要先控。”

运动：

```text
所有候选 token 回到外圈
当前示例“产品资料 → 销售话术 / 内容样板”进入中心缺口附近
四个诊断轴向这个 token 收敛
环上形成一个明确的选中槽
```

主标题收束为：

```text
先选一个
最值得验证的场景
```

页面必须保留“示例判断”标签，避免暗示这是对现场企业的真实结论。

#### Beat 19.7 — 现场自测入口展开

讲师触发：“接下来请大家用 3 分钟做一个自测。”

运动：

```text
雷达进入稳定低运动状态
QRDock 从右下展开
主二维码、短链和入口名称出现
四个扫描方向保持可读
候选场景退到外圈 40% 对比度
```

QRDock 文案：

```text
企业 AI 场景自测
约 3 分钟
```

手机表单承载六个完整问题；主屏不把六个问题全部展开。

讲师控制：

```text
T：启动 / 暂停 3 分钟计时器
Shift + T：重置计时器
```

计时器默认不启动。计时结束只做一次轻微结构提示，不播放警报音。

#### Beat 19.8 — 从自测回到行动判断

讲师触发：“有明确场景、有基础资料、负责人愿意参与，就适合进一步诊断和验证。”

运动：

```text
QRDock 缩为右下小型入口，不完全消失
四轴重新提高对比度
中心选中场景 token 与 SourcePacket、负责人节点、审核节点建立四点关系
场景槽由虚线变为完整实线
```

四个进入条件短暂出现：

```text
真实场景
基础资料
负责人参与
可控边界
```

#### Beat 19.9 — 扫描环从缺口展开为路线

讲师触发：“下一步不是继续听概念，而是拿真实资料跑一次。”

运动：

```text
ScenarioRadar 停止扫描
中心选中场景 token 进入接入环缺口
环的右侧分段从缺口处向前展开
圆形结构逐渐拉直为 ActionPath
四个诊断轴收拢为路线起点的判断节点
背景右侧开始出现暖白光面
```

Scene 20 的第一个节点 `今天` 在路径前方出现，但暂不展开内容。

- 四个诊断方向在 5 秒内可被观众读懂。
- 页面没有伪精确分数或自动推荐承诺。
- 六个候选场景属于同一套视觉系统。
- 自测时画面稳定、二维码清晰、无干扰动画。
- 选中场景能够无缝进入 ActionPath。
- 安全边界在诊断中仍作为内层条件存在。

## Scene 20 — 今天、30 分钟、3 天、3 个月

### 1. 叙事目的

把 Scene 19 选出的第一个场景变成一条可理解、可执行、不过度承诺的行动路径。

```text
3 天：用真实资料做出第一个样板

```

- 每个阶段的主要成果。
- 阶段之间的因果关系。
- 3 天与 3 个月的边界。
- 第一个样板如何从一次结果变成持续循环。

最终判断：

> 先判断，再验证，再固化。

### 3. 构图

ActionPath 从 Scene 19 的接入环右侧缺口向前展开。

- 聚焦当前节点时，容器扩大并显示成果。
- 讲解完成后，容器缩回路径节点。
- 上一个节点保留简短完成状态。

ProductStage 不在这幕全程保持大尺寸。它在 Day 2 节点重新成为样板主角，在其他节点缩为场景卡内的产品缩略锚点。

#### Beat 20.1 — 接入环完全展开为行动路线

#### Beat 20.2 — TODAY：看清趋势

- QRDock 的二维码、短链、说明和切换入口来自配置，不写死。
- 终幕进入后停止所有不必要动画循环，优先保证扫码和拍照稳定。
- 产品前后文字使用两个可访问性隐藏重复副本；屏幕阅读器只读取一次标题。
- Q&A 子模式保留 `returnState`，退出时还原 Scene 21.8。
- 不在终幕触发真实提交或收集数据；扫码后由外部表单负责。

### 13. 验收标准

- Scene 01 的缺口在 Scene 21 被真实样板填补，视觉闭环明确。
- 三句总结与课程主线一致，屏幕不过度拥挤。
- 产品穿字只在终幕关键 Beat 使用，不影响二维码读取。
- QR 入口清楚、可扫，并有短链降级。
- 终幕可稳定停留至少 10 分钟，不产生明显烧屏式高频运动或性能下降。
- Q&A 可进入、切换、退出，并准确恢复终幕。

### 4. Q&A 子模式规格

Q&A 不计入第 22 幕。它是 Scene 21 的可逆子状态，使用终幕已经形成的 CapabilityLoop 和共享内容容器。

#### 4.1 进入与退出

```text
Q：进入 / 退出 Q&A
Esc：返回 Scene 21.8
1—6：直接选择问题
← / →：切换问题
Enter / Space：展开当前答案的第二层提示
```

进入后：

- QRDock 缩为右下辅助状态，但保持可扫描。
- ProductStage 降低对比度，不卸载。
- CapabilityLoop 略微扩大。
- 六个问题 token 分布在外圈。
- 中央出现共享 `AnswerShell`。

退出后必须还原：

- 主标题位置。
- 产品对比度。
- QRDock 大小。
- CapabilityLoop 状态。
- 进入 Q&A 前的当前二维码入口。

#### 4.3 Q&A 视觉规则

# 16. 总版执行结论

Codex 不应一次性“做完整网站”。正确顺序是：

```text
先建立内容与绝对状态合同
→ 再建立演示控制壳
→ 再验证跨章节高风险转场
→ 再完成 21 幕静态终态
→ 再逐章补动画
→ 最后替换真实素材、做离线与现场压力测试
```

只有当静态画面、对象身份和前后恢复都稳定后，才允许加入更复杂的动效。视觉高级感主要来自连续对象、遮挡关系、共享容器和运动因果，不来自依赖数量或动画数量。
